# 教学策略：以理解为目标

用户确认：方法可以多元，但不能为了多样而多样。Harness 案例用于验收，不作为模型必须套用的示例。动画不是默认选项，也不是效果指标。

## 实现边界

教学策略单独放在 `server/app/pedagogy.py`，与模型接口及展示组件分离。课程不再规定固定顺序和 4–6 个内容块。问答可自由描述教学方法，仍通过现有组件显示；保存本轮教学目标、方法和待观察的理解证据，后续回答可参考。模型同时获得当前阅读位置附近的讲解、选中文字、近期对话与有效反馈。

这些改动提供选择能力和上下文，不能证明模型已经能稳定作出好的教学判断。已有课程不会被覆盖；无密钥的内置示例仍是预编写内容，不具备动态教学能力。动画场景引擎、代码执行区和课程目录筛选尚未完成。

## 真实模型验收场景

| 场景 | 观察重点，允许多种合格答案 |
| --- | --- |
| Harness 与 Environment 的边界混淆 | 能准确区分职责，可用类比、正反例或对照；不要求钢铁侠类比 |
| 只问某个术语的意思 | 简洁解释即可，不强行生成动画或测验 |
| 不理解递归的执行顺序 | 可以用逐步追踪、调用栈或小例子，注意终止条件 |
| 已看过类比，反馈仍然不懂 | 利用历史寻找具体卡点，可补前置知识、换角度或澄清，不能只复述 |
| 主动要求动画，但内容只是术语列表 | 说明最有帮助的表示方式；不把顺序高亮包装成复杂动画 |
| 数学概念中图形有助于理解 | 在展示能力允许时使用视觉方式，说明变化与不变量 |
| 原文不足以回答的问题 | 明确不足或澄清，不能借类比补造事实 |
| 用户已经得到清晰答案 | 可以停止，不强制练习、反复确认或自动推进章节 |

每次评估保留问题、来源、模型版本、完整回答和人工判断。先检查事实与引用，再检查解释是否针对难点、是否适量、是否诚实反映展示能力。理解证据通过用户自愿解释新例子或预测新结果收集，不以动画数量、方法种类数或点击完成作为掌握指标。

本次自动测试只证明：接口允许非视觉方式、自由教学方法可保存、后续反馈与当前讲解能进入模型上下文、问答不自动推进。模拟响应不能用于报告真实模型的教学效果。
